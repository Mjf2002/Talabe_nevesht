# راهنمای نسخهٔ چندزبانهٔ «منِ جمعی»

## وضعیت تحویل
- پیش‌فرض: فقط فارسی؛ ترجمهٔ خودکار خاموش است.
- شش آزمون مستقل موفق؛ بررسی TypeScript بدون خطا؛ بررسی نحوی JavaScript پنل موفق.
- ساخت محلی فارسی و ساخت آزمایشی فارسی/انگلیسی انجام شد؛ وجود متن انگلیسی در HTML خروجی بررسی شد. محتوای آزمایشی داخل بسته نیست.
- هشدار مهم: افزونهٔ @quartz-community/latex در محیط آزمون به دلیل native binding بارگذاری نشد؛ موفقیت ساخت، تأیید نمایش فرمول‌ها نیست. هشدارهای تاریخ بعضی نوشته‌ها و Sass نیز وجود داشت.
- انتشار واقعی، اتصال پنل به پوشه در مرورگر ویندوز و فراخوانی واقعی سرویس ترجمه آزموده نشده‌اند.

## ۱. نصب در پروژهٔ موجود
۱. ابتدا از پوشهٔ پروژه یک کپی پشتیبان بگیرید.
۲. ZIP را با Extract All باز کنید. پوشهٔ Talabe_nevesht-5 داخل آن پروژه است.
۳. در GitHub Desktop مخزن فعلی Mjf2002/javad و شاخهٔ v5 را نگه دارید. مخزن جدید نسازید.
۴. برای جلوگیری از بازنویسی نوشته‌های جدیدتان، پوشهٔ content داخل ZIP را روی محتوای فعلی کپی نکنید. فایل‌ها و پوشه‌های tools، quartz، i18n و فایل .github/workflows/deploy.yml را با نسخهٔ فعلی مقایسه و تغییرهای مربوط را منتقل کنید. اگر بعد از تحویل نسخهٔ پیشین تنظیمات یا کد را تغییر داده‌اید، این بخش‌ها نیز باید ادغام شوند، نه جایگزینی کورکورانه.
۵. فایل .gitignore شامل .i18n-build/ و .i18n-cache/ باشد.
۶. تغییرها را در GitHub Desktop بررسی، Commit و Push کنید. DNS، دامنه و شاخه را عوض نکنید.

## ۲. پنل پوشه‌ای
در Chrome یا Edge رایانه، tools/admin.html را باز کنید؛ «انتخاب پوشهٔ پروژه» و سپس ریشهٔ پروژه را انتخاب کنید. بخش جدید «زبان‌ها و ترجمه» است. این پنل پوشه‌ای است، نه پنل آنلاین OAuth.

عربی یا انگلیسی را انتخاب و تنظیمات را ذخیره کنید. برای هر زبان، ابتدا صفحهٔ content/index.md را انتخاب کنید، «باز کردن ترجمه» را بزنید و ترجمه را با frontmatter معتبر وارد و ذخیره کنید. نمونه:

```markdown
---
title: Home
---

Welcome to my website.
```

ترجمه‌ها در i18n/translations/en/ و i18n/translations/ar/ با همان مسیر فایل فارسی نگهداری می‌شوند. فایل فارسی بازنویسی نمی‌شود. تا وقتی index.md ترجمه نشده، آن زبان در انتخاب‌گر نشان داده نمی‌شود. انتخاب‌گر کاربر را به صفحهٔ خانهٔ زبان مقصد می‌برد، نه لزوماً ترجمهٔ همان صفحه.

در بخش تنظیمات مستقل، JSON هر زبان قابل ویرایش است. نام سایت، منو و فوتر مستقل‌اند. صفحهٔ خانهٔ ترجمه‌شده از Markdown خود آن زبان نمایش داده می‌شود؛ همهٔ باکس‌های ویژهٔ خانهٔ فارسی به‌صورت خودکار در خانهٔ زبان دوم بازسازی نمی‌شوند. بعضی ابزارها و برچسب‌های عمومی Quartz ممکن است همچنان فارسی بمانند.

## ۳. ترجمهٔ خودکار اختیاری
تنها اگر هزینه و ارسال محتوای عمومی به سرویس ترجمه را می‌پذیرید:
۱. در GitHub مخزن: Settings → Secrets and variables → Actions → New repository secret.
۲. نام دقیق: TRANSLATION_API_KEY؛ مقدار، کلید حساب OpenAI خودتان باشد. کلید را در چت، کد، JSON یا فایل عمومی نگذارید.
۳. در پنل، ترجمهٔ خودکار را روشن کنید؛ مدل مجاز حساب و محدودیت تعداد فایل جدید را تعیین کنید. سقف، مجموع فایل‌های عربی و انگلیسی در هر انتشار است؛ سقف هزینهٔ پولی نیست. کنترل بودجه را در حساب سرویس هم انجام دهید.
۴. Commit و Push کنید و نتیجه را در Actions بررسی کنید. صفحهٔ خانه اولویت دارد.

ترجمهٔ دستی از ترجمهٔ کش‌شده مقدم است و هرگز با خروجی خودکار بازنویسی نمی‌شود. نوشته‌های دارای draft، unlisted، password یا publish: false برای ترجمهٔ خودکار ارسال نمی‌شوند. این ویژگی جایگزین کنترل محرمانگی یا رمزگذاری نیست. ترجمهٔ خودکار نیازمند بازخوانی انسانی است، خصوصاً متون علمی و دینی و پیوندهای نسبی پیچیده.

کش Actions قابل حذف و تخلیه‌شدن است؛ اگر از بین برود، ترجمه‌های خودکار ممکن است دوباره تولید شوند و هزینه داشته باشند. ترجمه‌های نهایی را در مسیر ترجمهٔ دستی ذخیره کنید. کش فعلی با تغییر متن فارسی خودکار نوسازی نمی‌شود؛ برای اصلاح، ترجمهٔ دستی ثبت کنید. برای توقف هزینه، گزینهٔ خودکار را خاموش کنید.

## ۴. انتشار و آزمون محلی
در Settings → Pages، منبع انتشار GitHub Actions باشد. workflow موجود از شاخهٔ v5 استفاده می‌کند و خروجی را از محتوای تولیدشده می‌سازد. فایل‌های منبع جابه‌جا نمی‌شوند.

با Node.js 24 و npm:

```text
npm ci
node --test tools/prepare-languages.test.mjs
npx tsc --noEmit
npx quartz plugin install
node tools/prepare-languages.mjs
npx quartz build -d .i18n-build/content
```

پوشهٔ .i18n-build فقط خروجی تولیدی است؛ پوشهٔ content منبع اصلی باقی می‌ماند. مسیرهای content/ar و content/en رزرو شده‌اند؛ اگر موجود باشند اسکریپت متوقف می‌شود و آن‌ها را حذف نمی‌کند.

## حفظ اطلاعات
این بسته کلید یا رمز جدیدی ندارد. تنظیمات مخزن و DNS تغییر داده نشده‌اند. قبل از جایگزینی فایل‌های پروژه، نسخهٔ پشتیبان و بررسی diff ضروری است. پنل برای ذخیره‌ها از سازوکار پشتیبان قبلی استفاده می‌کند. این بسته جایگزین بستهٔ مجزای OAuth/آمار نیست.
